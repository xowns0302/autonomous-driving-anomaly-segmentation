# T1. 처리 시간 분석: 어디서 시간이 걸리나

- 날짜: 2026-10-17
- 목적: 논문 5장이 한계로 든 "DetSeg가 추가하는 시간"을 우리 환경에서 단계별로 측정하고, 줄일 수 있는 곳을 찾는다
- 결론: **DetSeg-S 시간의 절반 이상(54%)이 SAM이고, 그중 대부분이 GPU 계산이 아닌 CPU 전·후처리다.** 정확도를 바꾸지 않고 줄일 수 있는 부분이 크다

## 1. 방법

- `src/profile_latency.py`: 공식 코드를 그대로 돌리면서 단계마다 `torch.cuda.synchronize()` + 시간 측정. FS L&F 30장 (앞 5장 warm-up 제외), batch 1, GPU를 다른 작업과 공유하지 않음
- `src/profile_m2a_latency.py`: Mask2Anomaly 점수 지도 생성 (공식 계산과 동일: 원본 + 좌우반전 2회)
- 환경: RTX 4070 Ti, FS L&F 이미지 2048×1024

## 3. 어디를 줄일 수 있나

| # | 대상 | 지금 | 줄이는 방법 | 결과 변화 | 기대 절감 |
|---|---|---|---|---|---|
| 1 | **SAM 후처리** | box마다 mask 3장을 CPU에서 원본 크기로 키운 뒤 1장만 사용 | 쓰는 1장만, GPU에서 키우기 | **없음** (같은 mask) | ~170 ms |
| 2 | **SAM 전처리** | 같은 이미지를 2번 전처리 (두 번째는 결과를 버림) | 이미지 전처리 1번 + box 좌표 변환만 따로 | **없음** | ~60~100 ms |
| 3 | **글자 인코딩** | 매 이미지마다 같은 문장을 BERT로 다시 계산 | 처음 한 번 계산해 재사용 | **없음** | ~27 ms |
| 4 | 데이터 읽기 | 이미지 읽기를 계산과 순서대로 | 읽기를 별도 작업자로 겹치기 (공식 test.py는 이미 worker 2개) | 없음 | 체감 ~100 ms |
| 5 | 검출·SAM 계산 | fp32 | fp16 (반정밀도) | **조금 바뀔 수 있음** → 정확도 재확인 필요 | 검출·SAM encoder 30~50% |
| 6 | M2A | 원본 + 좌우반전 2회 | 1회만 | **점수 바뀜** (공식 계산과 달라짐) | ~210 ms |

1~3은 **결과가 완전히 같아야** 하는 변경이라 정확도를 다시 확인하기 쉽다 (IoU가 소수점까지 같아야 함). 합치면 DetSeg-S 808 ms → 약 **500~550 ms** 예상.

## 4. 논문 한계와의 관계

- 논문은 DetSeg-R의 추가 시간(77 ms)을 한계로 들었다. 우리 측정에서 **실제로 가장 큰 비용은 DetSeg-S의 SAM 부분이고, 그 대부분은 신경망 계산이 아니라 CPU 전·후처리 구현 방식**에서 나온다
- C5(I4)는 M2A를 추가하므로 DetSeg-S + C5는 약 1.3초다. 정확도 이득과 시간 비용의 trade-off로 보고한다. DetSeg-R + C5는 추가 비용이 거의 없다
