# A2. 실패 진단: OoD box는 어디서 잘못되는가

- 날짜: 2026-10-16
- 단계: Phase 2 (분석). 공개 코드·가중치 그대로, 관찰만 한다
- 배경: E1~E4에서 DetSeg-S·R 모두 FS L&F와 SMIYC Anomaly에서 실패했고, 두 방식이 같은 OoD box를 쓰므로 원인은 box 생성 단계로 좁혀졌다

## 1. 방법

1. `src/diag_ie_nms_sources.py`: detection만 실행(SAM 없음). IE-NMS 직전의 후보 전체(ID branch top-300 + UN query 300)를 이미지마다 저장하고, 최종 OoD box의 출처(UN / ID branch의 'objects' label)와 겹치는 ID box를 기록. 최종 box 수가 E4 ④와 같음을 확인 (예: FS L&F 1,051개)
2. `src/analyze_ie_nms_effect.py`: τ(0.2)를 넘는 OoD 후보 각각이 IE-NMS 뒤에 **남았는지 / 강화된 ID box에 지워졌는지 / 다른 이유로 지워졌는지** 분류
3. `src/diag_small_object_loss.py`: 정답 물체(10px 이상)마다 처음 실패한 단계 판정 (후보 없음 → ID label로만 잡힘 → 점수 ≤ 0.2 → NMS 제거 → 검출). 기준 box IoU ≥ 0.5
4. SMIYC Anomaly 이미지별 IoU 비교 (E4 결과)

"정답 위" = 정답 물체 box와 IoU ≥ 0.1, "오탐" = 그 외

## 2. 결과

### 2.1 IE-NMS는 무엇을 지우고 무엇을 남기나 (τ를 넘는 OoD 후보 기준)

| FS L&F | 2,318 | 844 (36%) | 523 (23%) | **951 (41%)** | 196 | 13 (7%) | 100 (51%) |
| Road Anomaly | 684 | 165 (24%) | 137 (20%) | **382 (56%)** | 480 | 32 (7%) | 230 (48%) |

("다른 이유로 지움"은 대부분 같은 물체의 중복 box가 일반 NMS로 정리된 것)

### 2.2 남은 OoD box가 올라앉은 ID box (IoU ≥ 0.5)

| Dataset | 남은 오탐 중 ID box 위 | 그 ID box 점수 p10/p50/p90 | 주요 class | 남은 정답 중 ID box 위 | 그 ID box 점수 p10/p50/p90 | 주요 class |
|---|---|---|---|---|---|---|
| FS L&F | 860 / 951 | 0.13 / **0.26** / 0.45 | car 439, person 86, truck 69 | 50 / 100 | 0.10 / **0.12** / 0.39 | pole, motorcycle, traffic sign |
| Road Anomaly | 243 / 382 | 0.11 / **0.21** / 0.43 | person 111, car 43 | 135 / 230 | 0.05 / **0.11** / 0.26 | person 54, pole 19 |
| FS Static | 430 / 486 | 0.14 / **0.25** / 0.44 | car 161, person 153 | 15 / 24 | 0.09 / **0.12** / 0.20 | person |
| SMIYC Anomaly | 81 / 111 | 0.08 / **0.10** / 0.32 | person 53, car 11 | 14 / 17 | 0.04 / **0.05** / 0.35 | person, traffic sign |
| SMIYC Obstacle | 41 / 42 | 0.07 / **0.16** / 0.19 | vegetation 23, wall 6 | 33 / 38 | 0.07 / **0.09** / 0.18 | **person 27** |

- 이 ID box들은 **하나도 bar를 넘지 못했다** (강화된 경우 0~1개). 즉 남은 오탐은 "ID branch가 class는 맞게 봤지만 점수가 bar보다 낮아서" 살아남았다
- **오탐 위 ID 점수(중앙 0.21~0.26)가 정답 위 ID 점수(중앙 0.05~0.12)보다 높다.** bar를 적절히 낮추면 오탐을 더 지우면서 정답은 대부분 지킬 여지가 있다. 다만 분포가 겹친다 (정답 p90 0.39 vs 오탐 p10 0.13)
- **SMIYC Obstacle: 정답 장애물 27개가 "person" ID box와 겹친다** (점수 0.09 수준). person bar를 0.09 아래로 내리면 실제 장애물이 지워진다 → 보정이 아닌 임의 조정은 위험하다

| Road Anomaly | 240 | 50 (21%) | 43 (18%) | 7 (3%) | 140 (58%) |

## 3. 결론

1. **IE-NMS는 작동하지만 불완전하다.** 오탐 후보의 24~57%를 지우지만, 33~73%는 남는다. 남은 오탐의 대부분(63~98%)은 ID 물체(차, 사람, 식생) 위에 있고, 그 ID box의 점수가 bar보다 낮다 → **bar가 이 가중치의 점수 분포보다 높다** (thing bar 0.5 vs 오탐 위 ID 점수 중앙 0.21~0.26)
2. **반대 방향의 실패도 있다 (과잉 억제).** 이상 물체가 ID class처럼 생기면(이미지 5의 truck) bar를 넘어 진짜 이상 물체를 지운다. 또 **stuff class(road) box가 큰 이상 물체를 지울 수 있다** (이미지 4). stuff class에 IE-NMS를 적용하는 설계 자체의 약점이다
3. **bar 값은 양쪽 실패의 균형점이다.** 낮추면 과소 억제가 줄고 과잉 억제가 늘어난다. 정답 위 ID 점수와 오탐 위 ID 점수가 분리되는 경향이 있어 개선 여지는 있지만, 평가셋을 보고 정하면 안 된다 → **A3: 논문 방식(Cityscapes)으로 보정**
4. **작은 장애물 손실은 IE-NMS 문제가 아니다.** 주원인은 objectness 점수 미달(τ)과 후보 미생성(해상도)이다. τ는 논문 핵심 주장이라 고정하므로, 개선 시 다른 방법(해상도 등)을 검토한다
