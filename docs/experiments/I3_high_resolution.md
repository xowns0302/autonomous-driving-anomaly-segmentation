# I3. 고해상도 추론 (C4) — 기각

- 날짜: 2026-10-17
- 단계: Phase 3 (개선), 계획: [05_improvement_plan.md](../05_improvement_plan.md)
- 결론: **입력 해상도를 키우면 성능이 크게 무너진다.** 기각

## 1. 목적과 설정

A2에서 FS L&F의 16px 미만 정답 중 45%가 후보조차 생기지 않았다. 입력을 덜 줄이면 작은 물체가 더 크게 보일 것이라는 가설.

- 입력 크기 (`FixScaleResize`, 비율 유지): 기본 짧은 변 800 / 긴 변 1333 → **1.25배 (1000/1666)**, **1.5배 (1200/2000)** (실행 전 고정)
- 기준선: 논문 방식 bar (A3 V1). 구현: `src/run_with_bars.py ... --cfg-options "test_dataloader.dataset.pipeline.1.scale=(1000,1666)"`. 실제 data loader에 적용됐음을 config 출력으로 확인

## 2. 결과 (튜닝셋, DetSeg-S IoU)

| 입력 크기 | FS L&F | Road Anomaly |
|---|---|---|
| 기본 (800/1333) | **24.26** | **79.25** |
| 1.25배 (1000/1666) | 10.72 | 69.30 |
| 1.5배 (1200/2000) | **0.32** | **9.60** |

## 3. 왜 무너지나 (Road Anomaly, 공개 bar로 진단: `results/I3/diag_ra_*`)

| 입력 크기 | IoU | 이미지당 box | box 넓이 중앙 / 상위 10% | box 점수 중앙 | 예측 면적 ÷ 정답 면적 (중앙) |
|---|---|---|---|---|---|
| 기본 | 76.46 | 10.2 | 2,766 / 42,342 | 0.371 | 1.06 |
| 1.5배 | 9.58 | 11.0 | 3,823 / 61,927 | 0.262 | 1.06 |

같은 이미지(소 두 마리)의 가장 큰 box: 기본 [204, 332, 530, 677] (정답 [206, 335, 543, 677]과 거의 일치) → 1.5배 [17, 264, 561, 707] (주변까지 크게 덮음)

- box 위치가 엉뚱한 곳으로 가지는 않는다 → **좌표 변환 오류가 아니다**
- 대신 **box가 커지고 엉성해지며, 점수가 낮아진다**. 모델(Grounding DINO + UN query)은 긴 변 1333 이하로 학습되었고, 그보다 큰 입력에서는 학습 때 본 적 없는 크기 분포가 되어 위치·크기 예측이 무너진다 (scale 분포 이동)
- 1.5배에서 IoU가 거의 0인 것은 box가 정답보다 크게 그려져 SAM이 엉뚱한 영역을 칠하기 때문으로 보인다

## 4. 결정

- 입력 확대는 기각. 사전학습 검출기의 학습 해상도 범위를 벗어나면 안 된다는 것이 확인됐다
- 작은 물체 누락을 해결하려면 **입력 크기는 그대로 두고, 이미지의 일부(예: 도로가 있는 아래쪽)를 잘라 기본 크기로 넣는 방식**(타일링)이 대안이다. 모델은 평소 크기의 이미지를 보지만, 그 안의 물체는 상대적으로 커진다. 계획에 없던 새 후보이므로 진행 여부는 사용자와 정한다
