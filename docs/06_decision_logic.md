# 06. DetSeg는 어떻게 이상 물체를 판단하고 점수를 매기나

[04_code_walkthrough.md](04_code_walkthrough.md)가 "어떤 코드가 실행되나"라면, 이 문서는 **"각 단계에서 무엇을 기준으로 남기고 지우는가"**를 실제 이미지 한 장의 숫자로 설명한다.

- 예시: FS L&F `10.png` (도로 위 상자 3개, [assets/figures/gt_examples.jpg](../assets/figures/gt_examples.jpg) 위쪽 줄)
- 설정: 공개본 그대로 (bar stuff 0.2 / thing 0.5, τ 0.2)
- 숫자 출처: `results/A2/fs_lostfound/candidates/0002.npz`, `results/E4/fs_lostfound_full/per_image.json`

---

## 0. "이상 물체"의 정의

DetSeg에서 이상 물체(OoD) = **"물체이긴 한데, 아는 19개 class(Cityscapes: road, car, person …)가 아닌 것"**

판단 논리는 두 문장이다.
1. 사진 속 **물체를 전부** 찾는다
2. 그중 **아는 물체로 확실한 것을 뺀** 나머지가 이상 물체다

이상 물체를 직접 배운 적은 없다. "물체 찾기"와 "아는 물체 알아보기"만 배웠고, 그 **차이**로 이상 물체를 정의한다.

---

## 1. 모델이 내놓는 점수 두 가지

| 점수 | 누가 | 의미 | 범위 | 어떻게 배웠나 |
|---|---|---|---|---|
| **class 점수** | ID query (900개 중 상위 300) | "이 box가 'car'라는 글자와 얼마나 맞나" (19개 class 각각) | 0~1 | Grounding DINO 원래 학습 (대량의 이미지-글자 데이터) |
| **objectness 점수** | UN query (300개) | "class는 몰라도 여기 물체가 있나" | 0~1 | DetSeg가 COCO로 추가 학습: COCO의 모든 물체 box = "물체", 나머지 = "물체 아님" |

모든 box는 [x1, y1, x2, y2] 좌표 + 점수 + label을 가진다. label 0 = "이상 물체 후보"(UN query 결과, 또는 ID query가 'objects' 글자에 가장 맞는 경우), label 1~19 = 아는 class.

---

## 2. 단계별로 남기고 지우는 기준 (실제 숫자)

### 단계 ① 후보 만들기 → **600개**

| | 개수 | 예 |
|---|---|---|
| ID branch | 300 | vegetation 45, building 33, road 27, wall 24, traffic light 22, sidewalk 21, pole 20 … ('objects' 18) |
| UN branch | 300 | 모두 label 0 |

여기서는 아무것도 버리지 않는다. 같은 물체에 box가 여러 개 겹쳐 있는 상태다.

### 단계 ② "확실한 아는 물체" 표시 (IE-NMS 1부)

**기준:** ID box의 class 점수 > 그 class의 **bar** 이면 "확실한 아는 물체" → 점수를 **×2** (경쟁용 임시 점수)

| class 종류 | bar (공개 코드) | 출처 |
|---|---|---|
| road, sidewalk, building, wall, fence, pole, traffic light, traffic sign, vegetation, terrain, sky | 0.2 | 코드에 고정 |
| person, rider, car, truck, bus, train, motorcycle, bicycle | 0.5 | 코드에 고정 |

→ 이 이미지에서 **53개**가 강화됨 (vegetation 11, traffic sign 8, building 7 …)

### 단계 ③ 겹치는 box 정리 (IE-NMS 2부 = NMS)

**기준:** 두 box가 **IoU > 0.5**로 겹치면, (임시) 점수가 높은 쪽만 남긴다. class는 따지지 않는다.

- box IoU = 두 상자의 겹친 넓이 ÷ 합친 넓이 (0 = 안 겹침, 1 = 완전히 같음)
- 강화된 ID box(×2)는 같은 자리의 이상 물체 후보를 이기기 쉽다 → **"아는 물체 위의 후보"가 여기서 지워지는 것이 IE-NMS의 목적**

→ 600개 중 **220개** 남음 (아는 물체 129, 이상 후보 91)

### 단계 ④ 아는 물체 box 버리기

**기준:** label이 1~19인 box는 모두 버린다 (역할을 다했으므로)

→ 이상 후보 **91개**

### 단계 ⑤ 점수 문턱 τ

**기준:** objectness(또는 'objects' 점수) **> 0.2**인 것만 남긴다. τ = 0.2는 논문이 정한 고정값이고, "물체 단위라 threshold에 둔감하다"는 것이 논문의 핵심 주장이다.

→ 77개 탈락, **최종 이상 물체 box 14개**

### 최종 14개는 무엇인가

| # | 점수 | 출처 | 정답과 IoU | 같은 자리 ID box | 판정 |
|---|---|---|---|---|---|
| 1 | 0.38 | ID('objects') | **0.90** | (없음) | ✅ 상자 |
| 2 | 0.37 | ID('objects') | **0.97** | (없음) | ✅ 상자 |
| 3 | 0.30 | ID('objects') | **0.93** | fence 0.18 | ✅ 상자 |
| 4 | 0.65 | UN | 0 | **person 0.48** (IoU 1.00) | ❌ 사람 |
| 5 | 0.56 | UN | 0 | **person 0.40** (IoU 0.99) | ❌ 사람 |
| 6 | 0.27 | UN | 0 | person 0.17 | ❌ 사람 |
| 7 | 0.25 | UN | 0 | motorcycle 0.23 | ❌ 오토바이 |
| 8 | 0.25 | UN | 0 | person 0.20 | ❌ 사람 |
| 9~11 | 0.22~0.23 | UN | 0 | car 0.13~0.19 | ❌ 차 |
| 12~14 | 0.24~0.26 | UN | 0 | traffic light / sign / vegetation 0.12~0.19 | ❌ 신호등·표지판·나무 |

- **정답 상자 3개는 모두 찾았다.**
- **오탐 11개는 전부 "아는 물체" 위에 있다.** ID branch가 class를 맞게 봤지만(person, car …), 점수가 bar보다 낮아(person 0.48 < 0.5) 강화되지 못했고, 그래서 이상 후보와의 경쟁(0.65 vs 0.48)에서 졌다.
- A3에서 보정한 bar(person 0.100)를 쓰면: person 0.48 > 0.100 → 강화되어 0.96 > 0.65 → **이 오탐이 지워진다.** bar 보정이 FS L&F를 올린 이유가 이것이다.

### 단계 ⑥ mask 만들기 (DetSeg-S)

**기준:** 최종 box 14개를 하나씩 SAM에 "이 상자 안의 물체를 따라 그려라"로 넣고, 나온 mask를 전부 합친다(OR).
SAM은 box가 맞는지 판단하지 않는다. **box가 오탐이면 mask도 오탐이 된다.**

→ 예측 픽셀 52,075개

### 단계 ⑦ 채점

**정답:** 데이터셋 제작자가 칠한 정답 mask (`labels_masks/10.png`: 1 = 이상, 0 = 정상, 255 = 제외)

**IoU (이미지 한 장):**

```
IoU = 겹친 픽셀 ÷ 합친 픽셀  (값 255 픽셀은 계산에서 제외)
    = 31,448 ÷ 51,463 = 61.1%
```

- 정답 픽셀 33,423개 중 31,448개를 맞힘 (상자 3개를 거의 다 칠함)
- 그런데 사람·차 위의 오탐이 합친 픽셀을 키워 61.1%에 그침
- 데이터셋 점수 = 모든 이미지 IoU의 **평균** (FS L&F 100장 평균 = 14.26)

## 3. 숫자 기준 한눈에

| 단계 | 기준 | 값 | 누가 정했나 |
|---|---|---|---|
| ② 확실한 아는 물체 | class 점수 > bar | stuff 0.2 / thing 0.5 (공개 코드), 논문은 Cityscapes로 보정 | 논문: 보정 / 코드: 고정 |
| ② 강화 | 점수 × λ | λ = 2 | 코드 (논문은 "λ배") |
| ③ 겹침 판정 | box IoU > 0.5 | 0.5 | 코드 (AP50과 같은 값) |
| ⑤ 최종 문턱 | 점수 > τ | 0.2 | 논문 |
| ⑦ 채점 제외 | 정답 값 255 | – | 데이터셋 |

## 4. DetSeg-R은 판단 방식이 같고 마지막만 다르다

①~⑤는 같다. ⑥에서 SAM 대신:
- 기존 방법(Mask2Anomaly)이 픽셀마다 매긴 "이상한 정도" 점수 지도를 받아서
- 최종 box **안쪽** 픽셀 점수에 **+1.0**을 더한다 → box 밖 오탐이 상대적으로 낮아진다

채점은 점수 지도용 지표를 쓴다.

| 지표 | 쉬운 뜻 | 좋은 방향 |
|---|---|---|
| AUROC | 이상 픽셀이 정상 픽셀보다 점수가 높을 확률 | ↑ |
| AP | 점수 높은 순으로 볼 때 이상 픽셀을 얼마나 정확하게 앞쪽에 모으나 | ↑ |
| FPR95 | 이상 픽셀 95%를 잡으려면 정상 픽셀을 몇 % 잘못 잡아야 하나 | ↓ |
| 최적 threshold IoU | 점수 지도를 0.01 간격 모든 문턱으로 잘라 보고 IoU가 최대인 값 (기존 방법에 유리한 조건) | ↑ |

## 5. 개선(Phase 3)이 바꾸는 곳

| 개선 | 바꾸는 단계 | 바꾸는 기준 |
|---|---|---|
| bar 보정 (A3, 기준선) | ② | bar를 Cityscapes로 계산한 값으로 |
| C1 배경 제외 | ③ | road·building 등 배경 class box는 이상 후보를 지울 수 없음 |
| C2 확신 보호 | ③ | objectness ≥ γ인 이상 후보는 ID box가 지울 수 없음 |
| C3 도로 문맥 | ⑤ 직전 | 도로 밖 후보 점수 × α |
| C4 고해상도 | ① 이전 | 이미지 축소를 덜 함 |

τ(⑤ 기준 0.2)는 바꾸지 않는다 (논문 핵심 주장).
